### 2. 체크리스트 중복 (🟡 중간)

**문제점**:
- 각 Phase마다 동일한 체크리스트 반복
- RED/GREEN/REFACTOR 각각 3-4개 체크박스

**예시**:
```markdown
# planner.md - TDD 구조
**RED Phase (테스트 먼저)**:
- [ ] 🔴 실패하는 테스트 먼저 작성
- [ ] 🔴 테스트 실패 확인 (빨간불)
- [ ] 🔴 테스트 설명 명확히 작성

# implementer.md - TDD Cycle
#### RED Phase (테스트 먼저)
- [ ] 🔴 실패하는 테스트 먼저 작성
- [ ] 🔴 테스트 실행하여 실패 확인 (빨간불 ❌)
- [ ] 🔴 테스트 설명 명확히 작성

# reviewer.md - TDD 검증
#### RED Phase 검증
- [ ] 🔴 테스트가 먼저 작성되었는지 확인 (git log, 커밋 히스토리)
- [ ] 🔴 테스트 설명이 명확한지 확인
- [ ] 🟡 테스트 실패 로그가 있는지 확인 (선택적)
```

**장황한 라인**: 약 80줄 (반복되는 체크리스트)

## 🔄 일관성 분석

### 1. 용어 불일치 (🟡 개선 필요)

#### a) "필수" vs "MUST" 혼용

| 파일 | 사용 패턴 |
|------|-----------|
| planner.md | "🔴 MUST", "필수 규칙", "반드시" |
| implementer.md | "🔴 MUST", "필수:", "반드시" |
| reviewer.md | "🔴 MUST", "필수:", "반드시 확인" |

**문제점**: 한글/영어/이모지를 혼용하여 일관성 부족

**개선안**: "🔴 MUST" 하나로 통일

---

#### b) TDD 용어 미묘한 차이

| 파일 | 용어 |
|------|------|
| planner.md | "TDD 구조", "RED Phase (테스트 먼저)" |
| implementer.md | "TDD Cycle", "RED Phase (테스트 먼저)" |
| reviewer.md | "TDD 검증", "RED Phase 검증" |

**문제점**: "구조" vs "Cycle" vs "검증" - 관점 차이가 명확하지 않음

**개선안**:
- planner: "TDD 계획"
- implementer: "TDD 실행"
- reviewer: "TDD 검증"
