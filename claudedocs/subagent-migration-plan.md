# 서브에이전트 기반 워크플로우 전환 계획

## 📋 프로젝트 개요

### 목표
스킬 기반 워크플로우를 서브에이전트 기반 아키텍처로 전환하여 컨텍스트 효율성과 구현 품질을 향상시킨다.

### 배경
현재 스킬 기반 워크플로우에서 다음과 같은 복합적인 문제들이 발생하고 있음:
- **컨텍스트 사용량 과다**: 플랜과 구현이 같은 세션에서 진행되어 메인 컨텍스트 부담
- **플랜 내용 손실**: 구현 단계에서 플랜의 세부사항이 누락되거나 잊혀짐
- **구현 품질 저하**: 긴 컨텍스트로 인해 구현 단계에서 집중도가 떨어짐

## 🎯 핵심 성공 지표

### 1. 컨텍스트 효율 (30%+ 감소)
- **측정 방법**: 메인 세션의 토큰 사용량 비교
- **목표**: 기존 대비 30% 이상 컨텍스트 사용량 감소
- **기대 효과**: 더 긴 대화, 더 많은 기능 개발 가능

### 2. 정보 무손실 (90%+ 전달)
- **측정 방법**: PLAN.md의 핵심 요구사항이 구현에 반영된 비율
- **목표**: 플랜의 90% 이상 요구사항이 정확히 구현됨
- **기대 효과**: 재작업 감소, 요구사항 충실도 향상

### 3. 구현 품질 향상
- **측정 항목**:
  - 테스트 커버리지
  - 코드 품질 (린트 에러, 타입 에러)
  - 아키텍처 일관성
- **기대 효과**: Fresh 컨텍스트로 더 집중된 고품질 구현

### 4. 워크플로우 속도
- **측정 방법**: 요청부터 완료까지 전체 시간
- **목표**: 불필요한 컨텍스트 로딩 제거로 더 빠른 응답
- **기대 효과**: 반복 사이클 단축, 생산성 향상

## 🏗️ 제안 아키텍처

### 서브에이전트 구조
```
User Request
    ↓
┌─────────────────────────────────────┐
│  Main Session (Orchestration)       │
│  - 사용자 요청 수신                    │
│  - 에이전트 라우팅 결정                 │
│  - 결과 통합 및 보고                   │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  Planner Agent (Fresh Context)      │
│  - 요구사항 분석                       │
│  - PRD 생성 (필요시)                  │
│  - Phase 분해 및 우선순위             │
│  - PLAN.md 작성                      │
└─────────────────────────────────────┘
    ↓ (PLAN.md)
┌─────────────────────────────────────┐
│  Implementer Agent (Fresh Context)  │
│  - PLAN.md 읽기 및 해석              │
│  - 프로젝트 타입 감지                  │
│  - 언어별 최적화 구현                  │
│  - 빌드/테스트 검증                    │
└─────────────────────────────────────┘
    ↓
    Result
```

### 컨텍스트 전달 메커니즘: 파일 기반 (PLAN.md)

**선택 이유**:
- ✅ 명확성: 플랜 내용이 파일로 명시적으로 저장됨
- ✅ 디버깅 용이: 파일을 직접 열어서 확인 가능
- ✅ 버전 관리: Git으로 플랜 변경 이력 추적 가능
- ✅ 재사용성: 동일 플랜으로 여러 번 구현 시도 가능

**PLAN.md 구조**:
```markdown
# [기능명] 구현 계획

## 목표
[구현 목표 및 배경]

## 요구사항
[핵심 기능 요구사항 목록]

## 아키텍처 결정
[주요 기술 선택 및 이유]

## 구현 Phase
### Phase 1: [단계명]
- 작업 1
- 작업 2
...

## 품질 기준
- 테스트 커버리지: XX%
- 빌드 성공
- 타입 체크 통과
```

## 📊 예상 결과

### 성공 시나리오
- **컨텍스트**: 메인 세션 부담 대폭 감소, 각 에이전트는 fresh context로 작업
- **품질**: 플랜과 구현이 명확히 분리되어 각 단계에 집중
- **속도**: 불필요한 컨텍스트 없이 효율적 작업
- **재사용**: PLAN.md 재활용으로 여러 구현 시도 가능

### 리스크 및 대응
| 리스크 | 영향 | 대응 방안 |
|--------|------|-----------|
| PLAN.md 품질 부족 | 높음 | Planner 에이전트 프롬프트 개선, 템플릿 강화 |
| 에이전트 간 컨텍스트 단절 | 중간 | PLAN.md에 충분한 상세 정보 포함, 참조 자료 링크 |
| 워크플로우 복잡도 증가 | 낮음 | 명확한 사용 가이드 작성, 자동화 스크립트 제공 |
| 오버헤드 증가 | 중간 | 성능 측정 후 최적화, 필요시 단순 작업은 기존 방식 유지 |
