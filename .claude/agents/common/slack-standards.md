# Slack 알림 표준 (Slack Notification Standards)

**참조**: Planner, Implementer, Reviewer 모두 이 Slack 알림 표준을 따릅니다.

## 기본 원칙

**필수**: 다음 3가지 상황에서 Slack 웹훅 알림을 전송해야 합니다.

## 3가지 필수 상황

### 1. Phase/Task 완료 시 🔴 MUST

**전송 시점**: 모든 서브태스크 완료 및 테스트 통과 후

**메시지 템플릿**:
```bash
./scripts/slack-notify.sh "**[프로젝트명]** Phase N 완료 ✅

**작업:** [작업 설명]
**경로:** $(pwd)
**테스트:** X/Y 통과, Z assertions
**커밋:** $(git rev-parse --short HEAD)

모든 서브태스크 완료. 다음 지시 대기 중입니다." "success"
```

**필수 포함 정보**:
- 프로젝트명 (대괄호로 강조)
- Phase/Task 번호
- 작업 설명 (한 줄 요약)
- 프로젝트 경로
- 테스트 결과 (통과 개수, assertion 수)
- 커밋 해시 (short)
- 상태 메시지

**예시**:
```bash
./scripts/slack-notify.sh "**[MyApp]** Phase 2 완료 ✅

**작업:** 사용자 인증 API 구현
**경로:** /Users/user/proj/myapp
**테스트:** 15/15 통과, 149 assertions
**커밋:** abc1234

모든 서브태스크 완료. 다음 지시 대기 중입니다." "success"
```

---

### 2. Phase/Task 실패 또는 타협 필요 시 🔴 MUST

**전송 시점**:
- 테스트 실패로 진행 불가 시
- 의존성 충돌 등 기술적 문제 발생 시
- 요구사항 변경이 필요한 경우

**메시지 템플릿**:
```bash
./scripts/slack-notify.sh "**[프로젝트명]** ⚠️ Phase N 실패

**작업:** [작업 설명]
**실패 이유:** [구체적인 실패 원인]

**제안 대안:**
1. [대안 1] (권장)
2. [대안 2]
3. [대안 3]

사용자 피드백 대기 중입니다." "warning"
```

**필수 포함 정보**:
- 실패 원인 명확히 설명
- 2-3개 구체적 대안 제시
- 권장 대안 표시
- 사용자 피드백 대기 명시

**예시**:
```bash
./scripts/slack-notify.sh "**[MyApp]** ⚠️ Phase 2 실패

**작업:** 사용자 인증 API 구현
**실패 이유:** JWT 라이브러리 버전 충돌 (jsonwebtoken 9.x vs 8.x)

**제안 대안:**
1. jsonwebtoken을 9.x로 업그레이드 (권장)
2. 8.x 호환 코드로 다운그레이드
3. 다른 JWT 라이브러리 사용 (jose)

사용자 피드백 대기 중입니다." "warning"
```

---

### 3. 더 나은 접근법 제안 시 🔴 MUST

**전송 시점**:
- 계획과 다른 더 나은 방법 발견 시
- 기술 스택 변경 제안 시
- 아키텍처 개선 제안 시

**메시지 템플릿**:
```bash
./scripts/slack-notify.sh "**[프로젝트명]** 💡 개선 제안

**현재 작업:** Phase N - [작업 설명]

**제안:** [개선 제안 요약]
**이유:**
- [이유 1]
- [이유 2]
- [이유 3]

**대안:** [기존 계획대로 진행]

승인해주시면 제안대로 진행하겠습니다." "info"
```

**필수 포함 정보**:
- 현재 작업 컨텍스트
- 제안 요약 (한 줄)
- 제안 이유 (2-3개 bullet points)
- 기존 계획 명시
- 사용자 승인 대기 명시

**예시**:
```bash
./scripts/slack-notify.sh "**[MyApp]** 💡 개선 제안

**현재 작업:** Phase 3 - 데이터베이스 스키마

**제안:** Prisma ORM 사용
**이유:**
- 타입 안정성 (TypeScript 네이티브)
- 마이그레이션 자동화
- 쿼리 빌더 내장

**대안:** 기존 계획대로 raw SQL 사용

승인해주시면 Prisma로 진행하겠습니다." "info"
```

## Slack 메시지 규칙

### 기술 규칙 🔴 MUST

- [ ] **스크립트**: `./scripts/slack-notify.sh` 사용
- [ ] **최대 길이**: 1000자 이내 (초과 시 요약)
- [ ] **언어**: 모든 메시지는 **한글**로 작성
- [ ] **상태 인자**: "success", "warning", "info" 중 하나

### 내용 규칙 🔴 MUST

- [ ] **프로젝트명**: 대괄호로 강조 `**[프로젝트명]**`
- [ ] **Phase/Task 번호**: 명확히 표시
- [ ] **상태 이모지**: ✅ (완료), ⚠️ (실패), 💡 (제안)
- [ ] **필수 정보**: 작업 설명, 상태, 관련 세부사항

### 형식 규칙 🟡 SHOULD

- [ ] **굵은 글씨**: `**레이블:**` 형식으로 구조화
- [ ] **Bullet Points**: 이유나 대안은 `-` 로 나열
- [ ] **간결성**: 핵심만 전달 (불필요한 설명 제거)
- [ ] **행동 요청**: 명확한 다음 단계 명시

## 예외 사항

### Slack 알림을 보내지 않는 경우

- 🟢 **MAY 수준의 작업**: 선택적 개선사항 완료
- 🟢 **중간 체크포인트**: Phase 내 서브태스크 완료 (Phase 전체는 알림 필수)
- 🟢 **리팩토링만**: 기능 변경 없는 코드 정리

### 주의사항

- ❌ Slack webhook이 설정되지 않은 경우 에러 처리 필요
- ❌ 테스트 환경에서는 알림 생략 가능 (환경 변수로 제어)
