# 우선순위 정의 (Priority Levels)

**참조**: Planner, Implementer, Reviewer 모두 이 우선순위 체계를 따릅니다.

## 우선순위 정의

| 표시 | 의미 | 위반 시 |
|-----|------|--------|
| 🔴 **MUST** | 필수 - 반드시 준수 | 작업 실패로 간주 |
| 🟡 **SHOULD** | 권장 - 강력히 권장 | 경고 후 진행 가능 |
| 🟢 **MAY** | 선택 - 상황에 따라 | 자유롭게 선택 |

## 사용 지침

### 🔴 MUST (필수)

**정의**: 반드시 준수해야 하는 필수 요구사항. 위반 시 작업 실패로 간주됩니다.

**적용 대상**:
- 핵심 기능 요구사항
- 보안 및 데이터 무결성
- 품질 검증 기준 (테스트 통과, 빌드 성공)
- 프로토콜 준수 (커밋, Slack 알림)

**예시**:
- 🔴 모든 테스트 통과
- 🔴 디버그 로깅 5가지 위치에 추가
- 🔴 Conventional Commit 형식 사용

### 🟡 SHOULD (권장)

**정의**: 강력히 권장되는 사항. 가능한 한 따라야 하지만, 정당한 사유가 있으면 경고 후 진행 가능합니다.

**적용 대상**:
- 코드 품질 개선사항
- 문서화 및 주석
- 최적화 및 리팩토링
- 부가적인 검증 항목

**예시**:
- 🟡 각 Phase는 독립적으로 테스트 가능
- 🟡 코드 품질 개선 (가독성, 유지보수성)
- 🟡 진행 상황 추적 테이블 작성

### 🟢 MAY (선택)

**정의**: 선택적 사항. 상황에 따라 자유롭게 선택할 수 있습니다.

**적용 대상**:
- 추가 문서화
- 향후 개선을 위한 제안
- 비핵심 기능
- 참고 자료

**예시**:
- 🟢 위험 요소 (⚠️): 예상 위험 및 완화 전략
- 🟢 참고 자료 (🔗): 관련 문서 링크
- 🟢 성능 최적화 제안

## 의사 결정 프로세스

### MUST 위반 시

1. **즉시 중단**: 작업을 중단하고 문제 해결
2. **원인 분석**: 왜 위반했는지 분석
3. **수정**: MUST 조건을 만족하도록 수정
4. **재검증**: 모든 MUST 조건 재확인
5. **진행**: 모든 MUST 통과 후 진행

### SHOULD 위반 시

1. **평가**: 위반 이유가 정당한지 평가
2. **문서화**: 위반 이유를 명확히 문서화
3. **경고**: 사용자/Reviewer에게 경고
4. **승인 대기**: 정당한 사유 시 진행 가능

### MAY 선택 시

- 자유롭게 선택
- 별도 승인 불필요
- 선택한 경우 완료 필요

## 예시: Phase 완료 조건

```markdown
### Phase 1 완료 조건

**🔴 MUST (필수)**:
- [ ] 모든 테스트 통과 (0 failures)
- [ ] 빌드 성공 (0 errors)
- [ ] 디버그 로깅 5가지 위치 추가
- [ ] Slack 알림 전송

**🟡 SHOULD (권장)**:
- [ ] 린트 통과 (0 errors, warnings 허용)
- [ ] 코드 리뷰 가능 상태
- [ ] 테스트 커버리지 ≥ 80%

**🟢 MAY (선택)**:
- [ ] 성능 최적화 (1ms 이하)
- [ ] 추가 문서화 (API 스펙)
```
